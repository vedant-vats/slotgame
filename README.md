# Lucky Slots: Unity Slot Machine

A classic 3-reel slot machine built in **Unity 6 (6000.6.10f1)** for the Slot Game assignment.
Spin with the button, the lever or the **Space** key. Line up three matching symbols on the payline to win.

## Game Overview

| Feature | How it works |
| --- | --- |
| **Winning logic** | You win when all 3 reels show the same symbol on the centre payline (marked by the red line and arrows). |
| **Reel animation** | Each reel winds up, accelerates, spins with a motion-blur stretch, decelerates onto its result and bounces into place. Reels stop left to right for suspense. |
| **RNG** | Each reel's result is rolled with a weighted random pick **before** the animation starts. The animation only presents a result that is already decided. |
| **Payouts** | Bet x symbol multiplier (see the paytable). Credits, bet and win meters roll up like a real cabinet. |
| **Bonus: progressive jackpot** | 5% of every bet grows the jackpot shown on the cabinet. Three **7s** pay 100x the bet **plus** the whole jackpot pool. |
| **Bonus: slam stop** | Press SPIN / Space / the lever again while spinning to stop the reels early. The result doesn't change. |
| **Bonus: auto spin** | Toggle AUTO to keep spinning. It stops on its own when credits run low. |
| **Win feel** | The payline flashes, coins burst out of the reels (more for bigger wins), and the cabinet shakes on big wins. |
| **Marquee lights** | Chase lights around the JACKPOT arch: slow when idle, fast while spinning, flashing together after a win. |
| **Showroom look** | Rotating sunburst behind the cabinet, twinkling stars, pulsing title, spinning rays behind the win popup. |
| **Music** | Looping casino-lounge track (toggle top-left) that ducks under big-win fanfares. |
| **Extras** | Clickable lever with pull animation, BIG WIN / JACKPOT popups, free refill dialog when broke, procedural sound effects. |

### Paytable (3 in a row on the payline)

| Symbol | Weight | Chance per reel | Pays |
| --- | --- | --- | --- |
| 7 | 1 | 10% | 100x + Jackpot |
| BAR | 2 | 20% | 25x |
| Bell | 3 | 30% | 10x |
| Cherry | 4 | 40% | 5x |

**Hit rate:** 10% (1 in 10 spins wins). **Line RTP:** 89%, plus the progressive jackpot.
These come from `Tools > Slot Game > Simulate 1,000,000 Spins`, which runs the real game code. The unit tests also check them.

## Running the WebGL Build

The build is in [`Build/WebGL`](Build/WebGL). Browsers block WebGL games opened from `file://`, so serve the folder over HTTP:

```bash
cd Build/WebGL
python -m http.server 8000
# then open http://localhost:8000
```

Any static server works (`npx serve`, VS Code Live Server, and so on). The build is gzip-compressed with
*decompression fallback*, so it also runs on hosts that don't send `Content-Encoding` headers, such as GitHub Pages.

**GitHub Pages (optional):** this repo includes `.github/workflows/deploy-webgl.yml`.
Enable it under *Settings > Pages > Source: GitHub Actions* and every push to `main` publishes `Build/WebGL`.

## Opening the Project

1. Open the folder in Unity Hub with **Unity 6000.6.10f1** (any Unity 6 should work).
2. Open `Assets/Scenes/SlotGame.unity` and press Play.

### Command-line workflow

The scene, prefabs, animations and data assets are generated by an editor script, so the whole game can be rebuilt headless:

```powershell
$unity = "C:\Program Files\Unity\Hub\Editor\6000.6.10f1\Editor\Unity.exe"
$project = (Get-Location).Path
# Rebuild scene, prefabs, animation clips and data assets
Start-Process $unity -Wait -ArgumentList "-batchmode -quit -projectPath `"$project`" -executeMethod SlotGame.EditorTools.SceneBuilder.Build -logFile builder.log"
# Run the unit tests (results in TestResults.xml)
Start-Process $unity -Wait -ArgumentList "-batchmode -projectPath `"$project`" -runTests -testPlatform EditMode -testResults TestResults.xml -logFile tests.log"
# Build WebGL into Build/WebGL
Start-Process $unity -Wait -ArgumentList "-batchmode -quit -projectPath `"$project`" -buildTarget WebGL -executeMethod SlotGame.EditorTools.BuildScript.BuildWebGL -logFile build.log"
```
Close the editor first: Unity can't open the same project twice.

The same actions are in the editor under **Tools > Slot Game**.

## Approach and Thought Process

**1. Decide first, animate second.** The core rule of a fair slot is that the result can't depend on the animation.
`SlotMachine.TrySpin` debits the bet and calls `OutcomeGenerator.Generate` *before* any reel moves.
The reels are then told where to land. Frame rate, timing and slam-stop can't change the result.

**2. Weighted, isolated RNG.** `WeightedPicker` builds a cumulative weight table and maps one roll into it,
so symbol odds are explicit and easy to tune. Randomness sits behind `IRandomProvider`. The outcome RNG is a private
`System.Random` instance, not the global `UnityEngine.Random`, so cosmetic effects can't shift results.
Tests inject seeded or scripted providers. A real-money product would put a certified RNG behind the same interface on a server.

**3. Separation of concerns (OOP).**
- *Core* classes are plain C# with no MonoBehaviour, so they are fully unit-testable.
- *Data* is ScriptableObjects, so designers can tune odds, payouts, bets and reel feel without code changes.
- *SlotMachine* owns rules and state and exposes **events**. The UI, audio and lever **observe** those events and never change
  state directly, so the presentation can be replaced without touching game logic.

**4. Reel motion.** A reel is modelled as an endless strip indexed by integers, with a float `position` in "cells".
Five pooled `Image`s are repositioned each frame for the visible indices, with no allocations during a spin. To stop, the
target symbol is written a few cells above the payline (out of view) and the reel decelerates with a cubic ease-out
whose duration is chosen so the starting velocity equals the spin speed. That makes the hand-off seamless. A small overshoot and
settle gives the mechanical "clunk". Reel motion is code-driven because the stop distance is only known at runtime.
UI motion that doesn't depend on runtime values (popups, lever, jackpot pulse) uses Animator clips.

**5. Reproducible scene.** `SceneBuilder` creates the scene, prefabs and animation clips from the raw art. The layout
is reviewable code and can be rebuilt from the CLI. It also fixes the sprite import settings (some art was auto-sliced
on import, e.g. the BAR symbol had been split into three).

**6. Testing.** EditMode tests cover payouts, the jackpot trigger, weighted distribution, zero-weight symbols, wallet
limits, jackpot growth and the theoretical RTP. The simulator checks the full loop over a million spins.
